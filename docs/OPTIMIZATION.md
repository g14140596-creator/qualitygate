# 检查点优化记录

## 发现的问题

首版20,000行、9规则合成负载中，纯引擎约108ms，但后台任务约4.7s。工作线程在每128次规则/行组合的检查点都建立SQLite连接，数据库访问频率远高于进度显示和人工取消需要。

## 改动

- 引擎仍每128个组合调用轻量检查点；服务关闭标记每次立即检查。
- SQLite取消读取、进度写入按50ms节流；末次检查点与最终提交事务强制检查取消。
- 数值上下界、跨字段比较函数按规则预解析，避免逐行构建比较字典及重复解析边界。
- 清理数据集列表重复返回的内部JSON字段，任务接口统一移除序列化存储字段。
- 为节流期间取消、计算完成后提交前取消、启动失败不打开浏览器等行为增加6项回归测试。

## 同进程对照

同一输入、同一已优化引擎、相同SQLite存储流程，交替运行3轮。唯一对照变量为工作线程检查点的数据库轮询间隔：0ms与50ms。

| 条件 | 3次耗时 / ms | 中位数 / ms |
|---|---|---|
| 不节流 | 4450.82、4623.26、4696.63 | 4623.26 |
| 50ms节流 | 144.57、156.70、143.95 | 144.57 |

本轮中位耗时减少96.87%；每轮断言两组汇总完全一致。完整机器、时间与样本记录见`benchmark.json`。这是本机合成负载，不是生产吞吐或用户并发压测；再次运行数值会变化。

## 未解决的边界

当前宿主沙箱启动的服务仍无法通过本机浏览器连接。桌面启动器具备真实健康检查与错误日志，但还需在普通Windows桌面中完成网络/浏览器验收。不将内存HTTP测试或VM页面渲染测试描述为端到端通过。
